# Ambiente Python — `uv`

> O `ct-mcp-server` executa Python via `uv` em ambiente efêmero controlado — sem fallback ao python do host.

## Como funciona

1. O servidor chama `uv` para criar um ambiente efêmero com a versão pinada do Python
2. Instala as deps (base + extras) via `uv`
3. Executa o script no ambiente
4. O ambiente é descartado após a execução (com cache)

## Variáveis de ambiente

| Env | Default | Descrição |
|---|---|---|
| `CT_MCP_UV` | `uv` | Caminho do binário `uv` |
| `CT_MCP_ML_PYTHON` | `3.14.5` | Versão do Python (passada como `--python <ver>`) |

## Deps em camadas

1. **Base** por família: `gbdt` → `scikit-learn==1.9.0` + `joblib==1.5.3`; `mlp` → `torch==2.12.0`; `centroide` → nenhuma
2. **Extras** do usuário: `deps: ["scipy==1.14.0"]` soma à base
3. As deps efetivas viajam no `ModeloFitado` para o `prever` montar o mesmo ambiente

## Instalação do `uv`

Se `uv` não estiver instalado, o servidor retorna erro com instrução:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## Limitações

- `uv` dá ambiente controlado, **NÃO é sandbox de segurança** — não barra FS/rede de script malicioso
- 1ª execução pode baixar Python/libs (rede); `uv` cacheia depois
- Sempre passa `--python <ver>` — o host precisa ter esse patch ou o `uv` o baixa como managed
