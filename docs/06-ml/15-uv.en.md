# Python Environment — `uv`

> The `ct-mcp-server` runs Python via `uv` in a controlled ephemeral environment — no fallback to host Python.

## How it works

1. The server calls `uv` to create an ephemeral environment with the pinned Python version
2. Installs deps (base + extras) via `uv`
3. Runs the script in the environment
4. The environment is discarded after execution (with cache)

## Environment variables

| Env | Default | Description |
|---|---|---|
| `CT_MCP_UV` | `uv` | Path to `uv` binary |
| `CT_MCP_ML_PYTHON` | `3.14.5` | Python version (passed as `--python <ver>`) |

## Layered deps

1. **Base** by family: `gbdt` → `scikit-learn==1.9.0` + `joblib==1.5.3`; `mlp` → `torch==2.12.0`; `centroide` → none
2. **User extras**: `deps: ["scipy==1.14.0"]` adds to base
3. Effective deps travel in `ModeloFitado` for `prever` to build the same environment

## Installing `uv`

If `uv` is not installed, the server returns an error with instructions:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## Limitations

- `uv` provides a controlled environment, **NOT a security sandbox** — doesn't block FS/network of malicious scripts
- 1st run may download Python/libs (network); `uv` caches afterwards
- Always passes `--python <ver>` — host needs that patch or `uv` downloads it as managed
