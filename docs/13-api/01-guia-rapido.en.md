# 01 — API Quick Start

The **CT Lab Desktop** internally runs an HTTP server (`ct-labd`) on port `8420`
(configurable). This server exposes a **REST API** that lets you trigger recipes,
manage agents, schedule cron jobs, swap prompts and send chat messages — all
programmatically from external applications (scripts, automations, CI/CD pipelines,
bots, etc.).

This guide is hands-on: in a few minutes you will make your first request and
understand the main flows. For the complete route reference, consult the
`ct-labd` server source code.

## Prerequisites

| Item | Detail |
|------|--------|
| CT Lab Desktop | Version with `ct-labd` enabled (check **Settings → App**) |
| Local port | `8420` by default — can be changed in **Settings → App → API Access** |
| Secret Key | Token generated in **Settings → App → API Access** |
| `curl` | Useful for quick terminal testing |
| Python ≥ 3.8 | For the Python examples (`requests`, `sseclient-py`) |
| Node.js ≥ 18 | For the JavaScript examples (native fetch, `EventSource`) |

> 💡 **Tip**: The server only accepts connections from `127.0.0.1` by default.
> For remote access, use the [tunnel](#tunnel-remote-access).

## Where to get the secret key

The API authentication uses a static **secret key** generated by CT Lab. To
get it:

1. Open **CT Lab Desktop**.
2. Navigate to **Settings → App → API Access**.
3. If there is no key yet, click **Generate**.
4. **Copy the value** — it is shown only once.
5. Ensure **Enable API server** is checked.

> ⚠️ **Treat the secret key as a password.** Never commit it to public
> repositories. Use environment variables (`CT_API_KEY`) or a secrets vault.

## Authentication

Every request (except [`/status`](#health-check) and `/features`) must include
the header:

```
X-Secret-Key: <your-secret-key>
```

Without the correct header, the server responds **401 Unauthorized**.

### Recommended environment variables

```bash
# Export once per shell session
export CT_API_KEY="your-secret-key-here"
export CT_API_URL="http://127.0.0.1:8420"
```

From here on, all examples assume these two variables are set.

## Health check

Before any authenticated call, check the server is up:

```bash
# /status does not require the X-Secret-Key header
curl -s http://127.0.0.1:8420/status | jq .
```

Expected response (example):

```json
{
  "status": "ok",
  "version": "1.4.2",
  "uptime_seconds": 3600
}
```

> ℹ️ `/features` is also public and returns enabled features (premium,
> extensions, etc.).

## First request: chat via `/reply`

The `POST /reply` endpoint sends a user message and returns an **SSE stream**
(`text/event-stream`) with the AI response in real time.

### Body structure

```json
{
  "session_id": "my-session-01",
  "user_message": {
    "role": "user",
    "content": [
      { "type": "text", "text": "Fetch BTCUSDT at 15m and calculate RSI(14)" }
    ]
  },
  "recipe_name": null,
  "override_conversation": false
}
```

### curl (live stream)

```bash
# -N disables buffering so you see the stream in real time
curl -N \
  -X POST "$CT_API_URL/reply" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "my-session-01",
    "user_message": {
      "role": "user",
      "content": [
        { "type": "text", "text": "Fetch BTCUSDT at 15m and calculate RSI(14)" }
      ]
    }
  }'
```

### SSE events

Each event is a line `data: {"type":"...", ...}\n\n`. The main types:

| `type` | What it represents |
|--------|---------------------|
| `Message` | A chunk (token) of the AI response |
| `Finish` | End of stream — contains `reason` (e.g. `"stop"`) |
| `Notification` | Message/notification from the agent |
| `UpdateConversation` | Snapshot of the updated conversation |
| `ActiveRequests` | IDs of in-flight requests |
| `Error` | Error — contains an `error` field |
| `Ping` | Keepalive |

Raw example:

```
data: {"type":"Message","message":{"role":"assistant","content":[{"type":"text","text":"Fetching"}]},"token_state":{"input":12,"output":3}}

data: {"type":"Message","message":{"role":"assistant","content":[{"type":"text","text":" BTCUSDT..."}]},"token_state":{"input":12,"output":8}}

data: {"type":"Finish","reason":"stop","token_state":{"input":12,"output":42}}
```

## Start an agent with a recipe

To run a recipe as an autonomous agent:

```bash
# 1. Start the agent with an existing recipe
curl -s -X POST "$CT_API_URL/agent/start" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "working_dir": "/home/user/project",
    "recipe_name": "rsi-daily-btc",
    "session_type": "plan_and_execute"
  }' | jq .
```

The response includes a `session_id` — keep it for subsequent calls:

```json
{
  "session_id": "agent-abc123",
  "status": "started"
}
```

### Other session operations

```bash
# List MCP tools available to the session
curl -s "$CT_API_URL/agent/tools?session_id=agent-abc123&extension_name=developer" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .

# Stop the agent
curl -s -X POST "$CT_API_URL/agent/stop" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "session_id": "agent-abc123" }' | jq .

# Switch provider/model at runtime
curl -s -X POST "$CT_API_URL/agent/update_provider" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "agent-abc123",
    "provider": "anthropic",
    "model": "claude-sonnet-4-20250514"
  }' | jq .
```

## Read an MCP resource directly

The `POST /agent/read_resource` endpoint reads an MCP resource without going
through the AI (model by-pass). Useful for scripts that want structured data
quickly:

```bash
curl -s -X POST "$CT_API_URL/agent/read_resource" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "agent-abc123",
    "extension_name": "developer",
    "uri": "file:///home/user/project/README.md"
  }' | jq .
```

> 💡 To list available resources, use `GET /agent/tools` with the `extension_name`
> filter and look for entries of type `resource`.

## Create and trigger a scheduled job

```bash
# 1. Create a job with a cron expression (runs every day at 09:00)
curl -s -X POST "$CT_API_URL/schedule/create" \
  -H "X-Secret-Key: $CT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "rsi-morning",
    "recipe": "rsi-daily-btc",
    "cron": "0 9 * * *"
  }' | jq .

# 2. Fire immediately (does not wait for the next cron tick)
curl -s -X POST "$CT_API_URL/schedule/rsi-morning/run_now" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .
# → { "session_id": "job-session-xyz" }

# 3. List all jobs
curl -s "$CT_API_URL/schedule/list" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .

# 4. Pause / resume
curl -s -X POST "$CT_API_URL/schedule/rsi-morning/pause" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .

curl -s -X POST "$CT_API_URL/schedule/rsi-morning/unpause" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .

# 5. Remove
curl -s -X DELETE "$CT_API_URL/schedule/delete/rsi-morning" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .
```

## Full Python example

Requires `pip install requests sseclient-py`.

```python
import os
import json
import requests

# Configuration
API_URL = os.environ["CT_API_URL"]            # http://127.0.0.1:8420
API_KEY = os.environ["CT_API_KEY"]            # your secret key
HEADERS = {
    "X-Secret-Key": API_KEY,
    "Content-Type": "application/json",
}

# --- 1. Health check ---
r = requests.get(f"{API_URL}/status")
print("status:", r.json())

# --- 2. List recipes ---
r = requests.get(f"{API_URL}/recipes/list", headers=HEADERS)
for recipe in r.json().get("recipes", []):
    print("-", recipe["id"], "—", recipe.get("title"))

# --- 3. Start agent ---
r = requests.post(f"{API_URL}/agent/start", headers=HEADERS, json={
    "working_dir": os.getcwd(),
    "recipe_name": "rsi-daily-btc",
})
session_id = r.json()["session_id"]
print("session_id:", session_id)

# --- 4. Chat via /reply with SSE stream ---
from sseclient import SSEClient

def stream_reply(session_id: str, message: str):
    """Send a message and print SSE tokens in real time."""
    body = {
        "session_id": session_id,
        "user_message": {
            "role": "user",
            "content": [{"type": "text", "text": message}],
        },
    }
    # stream=True + SSEClient to read the event-stream incrementally
    resp = requests.post(
        f"{API_URL}/reply",
        headers=HEADERS,
        json=body,
        stream=True,
    )
    resp.raise_for_status()

    client = SSEClient(resp)
    for event in client.events():
        data = json.loads(event.data)
        t = data.get("type")
        if t == "Message":
            # Concatenate the text from each response chunk
            for part in data["message"].get("content", []):
                if part.get("type") == "text":
                    print(part["text"], end="", flush=True)
        elif t == "Finish":
            print("\n[finish]", data.get("reason"))
            break
        elif t == "Error":
            print("\n[error]", data.get("error"))
            break

stream_reply(session_id, "Fetch BTCUSDT at 15m and calculate RSI(14)")

# --- 5. Stop the agent when done ---
requests.post(
    f"{API_URL}/agent/stop",
    headers=HEADERS,
    json={"session_id": session_id},
)
print("agent stopped")
```

## Full JavaScript/Node example

Uses native `fetch` (Node ≥ 18) and `EventSource` from the `eventsource` package.

```bash
npm install eventsource
```

```javascript
// api-quickstart.mjs
import EventSource from "eventsource";

const API_URL = process.env.CT_API_URL ?? "http://127.0.0.1:8420";
const API_KEY = process.env.CT_API_KEY;

if (!API_KEY) {
  console.error("Set CT_API_KEY in the environment.");
  process.exit(1);
}

const headers = {
  "X-Secret-Key": API_KEY,
  "Content-Type": "application/json",
};

// --- 1. Health check ---
const status = await (await fetch(`${API_URL}/status`)).json();
console.log("status:", status);

// --- 2. List recipes ---
const recipesResp = await fetch(`${API_URL}/recipes/list`, { headers });
const { recipes } = await recipesResp.json();
recipes.forEach((r) => console.log("-", r.id, "—", r.title));

// --- 3. Start agent ---
const startResp = await fetch(`${API_URL}/agent/start`, {
  method: "POST",
  headers,
  body: JSON.stringify({
    working_dir: process.cwd(),
    recipe_name: "rsi-daily-btc",
  }),
});
const { session_id } = await startResp.json();
console.log("session_id:", session_id);

// --- 4. Chat via /reply with SSE stream ---
// EventSource does not support POST or custom headers,
// so we use fetch manually with a ReadableStream reader.
async function streamReply(sessionId, message) {
  const resp = await fetch(`${API_URL}/reply`, {
    method: "POST",
    headers,
    body: JSON.stringify({
      session_id: sessionId,
      user_message: {
        role: "user",
        content: [{ type: "text", text: message }],
      },
    }),
  });

  const reader = resp.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  // Read the stream incrementally
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });

    // SSE: events separated by "\n\n"
    const parts = buffer.split("\n\n");
    buffer = parts.pop(); // keep the last incomplete fragment

    for (const part of parts) {
      const line = part.trim();
      if (!line.startsWith("data:")) continue;
      const evt = JSON.parse(line.slice(5).trim());

      if (evt.type === "Message") {
        for (const seg of evt.message?.content ?? []) {
          if (seg.type === "text") process.stdout.write(seg.text);
        }
      } else if (evt.type === "Finish") {
        console.log("\n[finish]", evt.reason);
        return;
      } else if (evt.type === "Error") {
        console.error("\n[error]", evt.error);
        return;
      }
    }
  }
}

await streamReply(session_id, "Fetch BTCUSDT at 15m and calculate RSI(14)");

// --- 5. Stop the agent when done ---
await fetch(`${API_URL}/agent/stop`, {
  method: "POST",
  headers,
  body: JSON.stringify({ session_id }),
});
console.log("agent stopped");
```

## Tunnel: remote access

By default `ct-labd` only listens on `127.0.0.1`. To expose the API remotely
(from a VPS, CI/CD, etc.), use the built-in **tunnel**:

```bash
# Start the tunnel
curl -s -X POST "$CT_API_URL/tunnel/start" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .

# Check status (returns the public URL + hostname + secret)
curl -s "$CT_API_URL/tunnel/status" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .
```

Response:

```json
{
  "state": "active",
  "url": "https://abc123.trycloudflare.com",
  "hostname": "abc123.trycloudflare.com",
  "secret": "tunnel-secret-xyz"
}
```

From now on, use the public URL as the base and keep the `X-Secret-Key` header.

```bash
# Stop the tunnel when no longer needed
curl -s -X POST "$CT_API_URL/tunnel/stop" \
  -H "X-Secret-Key: $CT_API_KEY" | jq .
```

> 🔒 **Security**: Even with the tunnel active, every request still needs the
> `X-Secret-Key` header. Never expose the public URL in logs or public channels.

## Troubleshooting

### `401 Unauthorized`

| Likely cause | Solution |
|--------------|----------|
| Missing `X-Secret-Key` header | Include the header on every request |
| Incorrect secret key | Regenerate it in **Settings → App → API Access** |
| Server restarted with a new key | Update the `CT_API_KEY` variable |

### `424 Failed Dependency`

| Likely cause | Solution |
|--------------|----------|
| Agent not initialized for the session | Run `/agent/start` before `/reply` |
| MCP extension disconnected | Check status in **Settings → Extensions**; restart the session |
| Non-existent working dir | Confirm the path in `working_dir` exists |

### Timeout / no response from `/reply`

| Likely cause | Solution |
|--------------|----------|
| AI provider has no API key configured | Set it in **Settings → AI Provider** |
| Provider rate limit | Reduce call frequency; use exponential backoff |
| Model too slow for the task | Switch to a faster model via `/agent/update_provider` |
| Connection closed before `Finish` | Resend the message; consider `override_conversation` |

### `ECONNREFUSED` (cannot connect to port 8420)

| Likely cause | Solution |
|--------------|----------|
| CT Lab Desktop is not running | Open the app |
| Custom port differs | Confirm the port number in **Settings → App → API Access** |
| Firewall blocking localhost | Allow port 8420 (or your custom port) for `127.0.0.1` |
